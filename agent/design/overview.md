# 视觉方向与信息架构

基线：用户此前确认的 Codex 风格个人工作区，palette 为 `current-codex-grayscale`。沿用现有灰阶、安静、信息明确的视觉；不重新设计品牌，也不复制其他产品的标志、商业音色或受限资源。

## 产品定位（2026-11-08 统一口径）

本项目是一个**硬件语音助手**：正常对话，理解需求，按需调用 API 与所选知识库把事办成，**简单、高效、快速**。

- 不缩减目标，也不扩大为多助手系统、长期记忆平台或重型规划 Agent。
- Agent 能力＝模型能根据目标和工具结果自己决定下一步（工具反馈循环），这已是现有底座；不做多助手、不做独立规划模型。

## 三层信息架构（目标设计，标注未实现部分）

1. **资源层＝全局可用状态**
   - **API 能力管理**：天气、M5 官方资料、自定义 API 合成**一个列表**（左列表＋右配置，参考图2）。底层 provider 不同，但在一处选择与管理。
   - **知识库管理**：**多个独立知识库**（左库列表＋右文档表，参考图3），文档有同步/索引状态、预览、重新上传、标签、删除。
   - 资源状态用「**启用 / 停用**」。
2. **助手层＝使用范围**
   - **一个助手**集中配置＝提示词 ＋ **选入哪些 API 能力** ＋ **选入哪些知识库**（参考图1）。复用现有「角色与声音」页扩展，不新建顶层页、不加「Agent 总开关」、不做多助手。
   - 选中态用「**选入本助手 / 未选**」，与资源层「启用/停用」严格区分，避免两份同名“启用”。
3. **对话层＝按需呈现**
   - 普通对话直接答；需要数据或资料时模型自己调用工具，按真实结果回答；连续两步沿用现有循环，不额外加规划模型。
   - 执行状态、出处、确认**只在需要时出现**，详情进数据洞察。写/付费操作需“提操作→确认→执行→回报”（当前缺口，未实现）。

## 现状（已实现，作为底座）

- 设置改为**整页两栏**（左导航＋右内容，独立滚动），不再用居中弹窗。
- 能力管理＝「工具 / 知识库」两个选项卡；工具里天气作为工具项、另有官方资料检索、个人资料检索、外部 API。
- API 配置工作台为整页视图：左请求列表＋右可视化/JSON＋参数/请求头/鉴权/请求体＋输出＋测试（已接近图2，可直接复用）。
- 数据洞察＝「知识库记录 / API记录」两选项卡，含筛选、详情、删除。
- 知识库：可上传、资料列表、查看内容（正文/分段片段）、试查。
- **尚未实现（目标）**：助手层的“提示词＋选择 API/知识库”绑定；多独立知识库；写操作确认闭环。

## 视觉与设备约束

- 保留明暗主题、会话侧栏、底部输入区、沉浸式网页语音界面（中央状态球表达真实录音/生成/播放）。
- 状态必须区分「配置已保存」「指令已发送」「设备已确认」「实际效果已验证」；**未运行不写成已可用**。
- 管理网页与 128×128 设备屏分别设计；设备屏只显示状态、短文字和必要表情，不把网页表单缩进设备屏。

旧的「居中设置窗口 920×720」「角色 / API接入 / 设备 三页签」「资料与用量页已移除」等旧结构已被整页两栏＋能力管理两选项卡取代，不再作为规范。

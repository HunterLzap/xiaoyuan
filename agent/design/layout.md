# 布局、文字与动效

下列为现有实现提取的基线，不是本轮重排页面的任务。

- 字体：`Segoe UI Variable`、`Segoe UI`、`Microsoft YaHei`、系统sans-serif；代码用Consolas/Cascadia Code。使用系统字体，不为规范化下载字体。
- 正文14px、行高1.6；标题约28px，手机约24px。辅助信息不能通过过小字号承载关键失败或费用说明。
- 桌面侧栏252px；960px以内现有缩为222px；700px以内隐藏为可展开的252px侧栏。内容列必须允许 `min-width: 0`，避免长地址撑破布局。
- 工具栏桌面60px、窄屏54px；普通图标按钮32px。触控入口不足时扩大可点击区域，不靠细小图标承担唯一操作。
- 对话居中、消息区滚动、输入区底部固定在工作区内；设置各页复用同一shell，避免每页重复导航。
- 保留现有7–8px控件、10–12px容器、16px输入圆角。新增间距沿用邻近页面，优先8/12/16/24/32px，不为了统一把已有数值全部改写。
- 短动效仅解释状态和反馈；尊重 `prefers-reduced-motion`。不在管理任务中增加持续装饰动画。

## 信息架构布局

三张参考图对应三层；现有助手/多库页面已落地，布局规范如下，实际运行证据看progress，不在此维护完成表：

- **助手配置页**：复用现有「角色与声音」页，单列自上而下＝提示词（多行）→「API 能力」选择区（可勾选列表）→「知识库」选择区（可勾选多库）。不额外堆独立区域，不新增 Agent 总开关。
- **API 能力管理**：左列表（约 260px）＋右侧配置区（可视化/JSON、参数/请求头/鉴权/请求体、输出、测试），沿用现有 api-workbench 两栏，改为填满右侧内容宽度。
- **知识库管理**：左库列表＋右文档表（同步状态单行，沿用列表分页），操作入口收进行内。
- 表单类页面（API 接入、声音）保持限宽；能力/知识库等表格式页面用满右侧宽度，不被 700px 挤在中间。

## 响应式与设备屏

界面变更按实际影响核对桌面、390px窄屏以及明暗主题；文档整理不触发浏览器/模型检查。模型ID、地址、错误文案可换行；代码块单独横向滚动，不让整个页面溢出。

128×128设备屏只显示状态、短文字和必要表情。字体、截断、翻页与声音同步需实机设计与验证；现有网页字号和布局不能直接当屏幕资源规范。

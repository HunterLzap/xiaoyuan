# 命名规范

- 现有原生JS函数和状态使用camelCase；不引入与当前栈不符的React组件文件命名规则。
- CSS类和DOM id使用kebab-case，复用 `settings-row`、`session-item` 等已有语义；主题变量沿用tokens文件中的名称。
- SVG symbol沿用 `i-功能` 命名，通过既有sprite复用，不给同一动作增加多个风格不同的图标。
- 新视觉资源建议用 `用途-名称-变体.扩展名`；音频样例沿用 `模型-音色-速度`，结果度量与音频同名。
- UI使用用户能理解的“模型”“声音”“设备”“历史”；内部ASR/TTS/Opus仅在诊断或必要配置说明中展示。
- 产品名沿用当前项目，不因聊天中的不确定称呼自动改名或引入品牌资源。

## 单助手三层命名（2026-11-08）

- 三层：**资源层**（API 能力、知识库）、**助手层**（助手配置）、**对话层**。
- 术语区分：资源用「**启用 / 停用**」（全局是否可用）；助手用「**选入本助手 / 未选**」（使用范围）。禁止两处都用“启用”，避免用户混淆。
- 界面用词：「API 能力」「知识库」「助手配置」「提示词」；不在界面上用“Agent/智能体”作为开关或标题。
- 个人知识库检索**不作为独立工具项**出现，它由助手选入的知识库决定；不重复展示“个人资料检索”开关。

所有新命名应与 [代码结构](../code/structure.md) 和 [资源规则](assets.md) 一致，不重命名现有路径来制造整齐。

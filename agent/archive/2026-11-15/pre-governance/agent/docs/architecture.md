# 单硬件语音助手：目标与整体设计

更新：2026-11-15。当前实现与实际范围见下方最新记录和progress；早期调研建议保留为历史，不再据其判断当前“尚未实现”。

## 1. 目标与现状

### 2026-11-15 调查确认：查询日期覆盖与转写后响应控制（尚未接入）

同一真实供应商连接，完整文字手动触发：首问get_weather(city=北京,days=1)成功，仅含2026-11-15、4.1～11.2℃；“那明天呢”时上游仍确认7工具，三个函数事件入口均无调用，却把同一数据用于11月16日。这次跳调用不由转写迟到、VAD抢答或工具缺失解释。可定位的应用缺口是查询结果缺乏目标城市/日期覆盖检查；只按任务提供定义不足以保证模型真正取数。百炼[官方Function Calling](https://help.aliyun.com/zh/model-studio/qwen-function-calling)明确Realtime不支持tool_choice/parallel_tool_calls，不能用required保证。

已实连当前模型，`turn_detection={type:server_vad,create_response:false,interrupt_response:true}`被session.updated原样回显，分段参数保留，恢复true也确认；未发送音频，因此仅确认配置接受，没有确认实际音频分段/完整转写/取消与首响行为。参考[LiveKit官方PR6642](https://github.com/livekit/agents/pull/6642)与[当前实现](https://github.com/livekit/agents/blob/main/livekit-agents/livekit/agents/llm/_realtime/openai.py)：将“谁分段”和“谁触发回答”分开，打断开关独立处理；不照抄其默认打断策略。百炼[客户端事件](https://help.aliyun.com/zh/model-studio/client-events)和[服务端默认会话](https://help.aliyun.com/zh/model-studio/server-events)为实际协议依据，供应商间行为不可直接等同。

接入方案沿用一个助手、现有模型/音色/音频与工具循环，不增加每轮规划/分类模型：

| 代码落点 | 需要接入的行为 |
| --- | --- |
| realtime.open | 保留server_vad及原阈值/静音/采样/音色，配置不自动回答；不能直接关掉VAD要求设备另发停录。 |
| realtime.receive | 完整转写后先执行原结束意图分支；其余创建带当前turn_id的准备任务，最近结构化任务参数＋候选工具并集保留复合需求和追问。 |
| refresh_tools / session.updated | 单个接收循环解析确认，准备任务等待确认后response.create；不能在同一个receive处理分支自等由自身读取的确认，避免卡死聆听。 |
| text_tool_selection | 抽取/复用选择与同轮补充加载，参数化文字/语音描述；不能直接把文字compact规则或生命周期复制到语音。 |
| TurnTools / 历史工具记录 | 保留必要的真实查询参数、城市、目标/结果覆盖日期、时间/来源与成功状态；当前天气summaries仅工具名/状态不够，不能据助手口头回答构造事实。 |
| output_blocked / run_tools | 对已明确的查询延续检查真实结果是否覆盖目标；不覆盖先实际查，失败如实播报，再走原模型声音。不能只加“必须查”的提示，也不能用无真实调用的call_id伪造工具输出。 |

参考[LangChain工具与State](https://docs.langchain.com/oss/python/langchain/tools)的会话工具状态及动态选择机制。明确天气话题后的“那明天呢”可续接城市、改目标日期；已有成功数据覆盖目标时可以复用，不机械每轮重查。“明天”不能全局映射天气，订单/其他任务按自身最近真实状态续接；新话题结束旧续接，复合指令取并集且保留加载入口。

speech_started继续取消旧准备/工具任务并沿用原turn_id/迟到隔离；“退下”等继续直接回原idle，不经过加载工具。模型、音色、音频帧/缓冲、设备唤醒/播放/待机与OTA/动画均保留。本轮只调查并更新此方案，云端和本机运行链未切换。实测证据见logs/voice-routing-investigation-20261115.json与progress；后续须用真实音频确认配置行为和首响，不能以session.updated回显代替听感。

### 2026-11-15 语音首批：共用用量/控制校验，提示只删重复

当前云端 `bd639a9-voice-20261115`。语音复用既有Token模态/逐响应用量与控制意图校验，仍提供全部已开放工具；不接TextToolSelection。最终只从语音提示删除与Schema重复的工具名单和末尾重复闲聊提醒，原通用规则、角色、朗读/完整报数及追问规则原文和顺序保留。7工具提示少187字符，不作为Token节省账单；音频接收/播放/传输、VAD、打断/结束回待机不改。文字提示保持原文。本机代码已同步但旧进程重启被自动审批拒绝，不能把云端已加载写成本机设备已生效。

完整转写后再选工具是可行设计，但当前语音由server_vad自动触发首响应，完整转写可能晚于响应开始。只有协调响应触发与工具定义确认，才能保证首响应使用选定工具；单在转写回调换定义不足以保证。未来沿用原turn_id、取消与结束意图，保留复合需求并集、追问和缺失能力的同轮加载；不未经验证照搬其他供应商的create_response开关或拆换现有音频模型链。

真实文字驱动语音探查出现天气追问跳工具，补提示未可靠解决，已退回只删重复的版本；未定位其与稳定真机/本轮去重的因果。供应商直连探查不包含生产控制补执行，实际设备出声/唤醒/打断/待机未复验。证据与未解决项见progress，后续不靠继续堆提示冒充执行保证。

### 2026-11-15 网页文字按任务工具选择

只在现有RealtimeTextProvider使用 `TextToolSelection`：任务线索＋控制计划＋最近一轮真实工具记录预加载，复合需求取并集；线索不充当权限或能力硬过滤。其余已启用能力通过 `_load_task_tools` 在同轮加载，采用原TurnTools/ToolRegistry/审计和百炼session.update/session.updated，加载后正常工具调用再拿真实结果。参数Schema在函数定义及加载回填中提供，防止模型套用常见但错误的参数名。

借鉴[LangChain动态工具选择](https://docs.langchain.com/oss/python/langchain/tools#dynamic-tool-selection)与[Anthropic按需工具加载](https://www.anthropic.com/research/advanced-tool-use)。工具少时先搜索可能增加成本，所以常用/明确/追问能力直接下发，未知需求保留加载入口；不引入框架、每轮前置分类/规划模型或供应商专属defer_loading字段。加载不占业务8调用/4轮额度，但其响应次数和Token照常统计。未预选工具可访问不等于每次更省/更快。

语音入口仍用完整工具，不接选择器；语音提示去重以本节上方首批记录为准。以下真实范围仅网页文字：报数/寒暄各少466输入、约28%；天气与“那明天呢”直接调用；天气＋个人资料复合成功；未预选的晾被子气象任务成功加载并查询。未知任务样本3次模型响应，普通天气2次。详见progress。

### 2026-11-15 网页文字提示精简与计量

`build_system_prompt(..., compact=True)`仅由实时网页文字入口启用；voice强制关闭，其他原调用默认完整规则，自定义业务/订单场景保留完整系统规则。角色提示保持原文，文字合并重复内置规则，工具说明在深拷贝中精简，参数约束与原全局定义不变。语音完整提示和音频模块与上一版逐字比对一致，不将网页文字收益冒充语音收益。

同一模型/报数请求的逐块usage差分复现2236输入：问题/协议23、角色597、时间/诚实135、工具规则431、重复提醒62、工具定义988；分项是固定顺序边际差值而非供应商逐项账单。最终文字输入1676/输出6，少560约25%；截图寒暄2227→1667。旧历史本轮无占用，四工具未调用时定义仍进上下文。

参考[Anthropic上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)、[工具说明设计](https://www.anthropic.com/research/writing-tools-for-agents)、[LangChain动态调用入口](https://docs.langchain.com/oss/python/langchain/middleware/custom#dynamically-selecting-tools)。保留明确触发/参数语义；实际曾因过短状态说明引发误查询，已恢复，不以盲目删工具或每轮增加分类模型来追求最低输入。后续按任务选择与同轮补充已落实，见上节，现有查询能力继续保留。

### 2026-11-15 已实施：工具执行意图、用量与会话内检索

- `TurnTools`在执行前核对控制意图与明确目标；文字减少本轮无关的可变更工具，实时仅可变更控制等待转写。复用权限/Schema/设备回读/取消隔离，不增加前置规划模型。参考[OpenAI工具guardrails](https://openai.github.io/openai-agents-python/guardrails/)，未引入SDK或替换运行循环。
- `TokenUsage.from_provider`保存供应商模态/缓存明细，`combine_usage`保留逐次用量与完整性。页面原生折叠展开；旧数据不反推、缺项不填0、缓存不与输入重复相加，费用按供应商适用定价/账单。
- SQLite保存完整原文，活动历史按完整轮次＋6000字符预算重建，超长单条保留有省略标记的首尾。只读 `search_conversation_history` 绑定当前会话，支持关键词/角色/时间排序，返回有限原文与状态。参考[LangChain短期记忆](https://docs.langchain.com/oss/python/langchain/short-term-memory)的持久化/裁剪/按需读取机制，不加框架、向量模型、每轮总结或永久画像。
- 字符预算只约束文本请求/新实时连接重建；同一百炼实时WS仍由供应商保存上下文，未主动删除旧item。不使用未确认的delete/truncate或压缩式重连。模型/音色/音频收发播放/OTA/新动画边界不变，真实证据见progress。

### 2026-11-15 历史调研建议（当时未实施，后续落实见上）

用户要求参照成熟产品评估现有Agent设计、解释记忆/Token开销，并明确显示用量；本轮只落实前端用量显示，不据此授权重写实时链路、改模型或添加长期记忆。现有单助手、百炼实时主线、音色、设备OTA及新动画隔离边界继续保留。

- 代码事实：`ToolRegistry`已有选用范围、JSON Schema、权限与设备回读，但四个设备/声音工具只要对应对象存在就入注册表，文字报数请求也会看到音量工具；`TurnTools.execute`没有统一的本轮控制意图授权。真实误调用为模型生成volume=50，现有正向control_plan对该报数请求返回空，不能称为服务端规则误解析。
- 上下文事实：SQLite完整历史与最近六轮完整对话已分离；文字路径每次新建供应商连接并发送提示/工具定义/所选历史，实时语音同一连接由供应商保留上下文。当前六轮限制不等于实时连接中旧item被删除；未实现按Token预算的实时上下文整理。被中断消息在本地完整历史保留，但重建活动文本上下文会排除未完成助手消息；不能再写成“每轮都重发完整历史/中断报数全文”。
- 计量事实：当前只保存供应商input/output/total三项；实时输出可能混合文本与音频。截图4355=输入4321+输出34，无法用已有三项精确拆出系统提示、历史、文本/音频、缓存各占多少。前端已显式显示输入/输出/合计，缺项不填0；后续应在稳定模块独立改版中保留input_tokens_details/output_tokens_details及每轮响应次数，账单仍以实际分模态价格与供应商账单为准。

建议按实际问题推进，均未实现：

1. 优先补设备控制的意图边界和能力可用性，统一到工具执行层，复用已有控制/否定/上下文规则；先区分直接回答、查询、控制，避免纯报数控制音量，也不能误拦“先调音量再报数”的复合任务。语音转写迟到时不能仅凭模型猜出的工具参数执行；不增加每轮必走的规划/分类模型调用。
2. 精简基础提示和工具描述，校正用途/参数/失败反馈，用真实失败会话检查误调用、漏调用、参数和最终结果；当前工具少，不先引入大型工具检索或多Agent框架。按状态和场景限制动作，不在实时流中任意增删工具或反复重连。
3. 上下文按Token预算保留近期对话、当前话题和未完成事项；长报数/长工具结果可在后续活动上下文中压缩为保留关键事实的短状态，SQLite原文与历史不删。问题需要旧内容时再检索。总结也有成本、丢细节风险，宜按阈值/话题切换触发，不每轮增加一次总结请求。
4. 知识库继续按需取片段；用户偏好等跨会话记忆若后续需要，应单独明确记什么、如何修改/删除及何时检索，不默认把全部聊天做成永久画像。数据库存储不等于模型能免费读取记忆，检索出的部分仍占上下文。
5. 缓存是单独的优化项：先核实当前Qwen3.8-Omni-Flash-Realtime接口与实返字段，不套用非实时Omni/Chat Completions的cache_control或其他模型tool_choice/item删除接口；当前官方缓存支持列表未据此确认实时主线可用。未验证前不承诺缓存折扣或节省比例。

一个硬件语音助手（AtomS3R + Echo Base）：正常对话，理解用户想做什么，按需调用 API 与所选知识库，用真实结果达成需求；简单、高效、快速。不缩成普通聊天，也不扩大为多助手系统或复杂 Agent 平台。

这里 Agent 指模型依据目标和工具结果决定下一步的反馈循环。长期记忆、多助手、独立规划器、外部写操作不是定义的必要条件；四轮循环上限也不代表只能查一步。此前 L1/L2 分类废止，不再作为产品或验收标准。概念参考 [Anthropic — Building effective agents](https://www.anthropic.com/research/building-effective-agents)，工程流程仍按本项目约定。

已有底座：百炼原生实时音频、工具注册/校验/执行/结果回填、提示构建、个人知识检索、历史和洞察。基础设备交流与实时文字 RAG 有各自真实证据。待补：单助手 API/库选择、多库归属/硬过滤、资源与配置页面联动及清楚的执行呈现。外部写操作尚无完整对话确认，不宣称已具备通用代办。具体状态只看 [progress](progress.md)。

## 2. 结构与复用边界

```text
设备语音 / 网页语音 / 网页文字
              ↓
现有会话与轮次上下文（当前设置、目标、历史、取消标识）
              ↓
共用策略：提示构建、所选能力、参数/权限、执行结果、审计
              ↕
模型工具反馈循环（原生实时 WS / 分模型适配）
              ↓
统一工具目录与执行器
 ├─ 内置：天气、M5Stack 官方资料、已开放设备/声音控制
 ├─ 自定义 HTTP API
 └─ 知识检索：仅本助手选中的库
              ↓
既有私有配置与 SQLite 原文/片段/向量/历史/洞察
```

共享业务策略与执行契约，保留不同模型的原生传输。设备/网页语音继续使用百炼实时音频，不改成文本后再走 MiMo，不切换已跑通音色；实时模式文字与分模型分别适配同一执行规则。不增加每轮必走的规划调用，不新造调度平台。

沿用 FastAPI、原生页面、SQLite、ToolRegistry/TurnTools、SettingsStore。当前四轮/八次上限保留为执行边界，任务达到上限要如实答复，不能无限循环或编造完成。未来目标云机 2 核约 1.87GB，仅做存储/检索，重模型走云端；这不是当前 Windows 本机配置，也不是已部署验收结论。

## 3. 设置与资源：三层关系

**资源管理**负责配置、可用状态和资料，不决定本助手选用范围。

- API 能力统一列表包含天气、M5Stack、自定义 API。内置与 HTTP 底层不同，同一列表不意味着给内置能力伪造 URL；设备控制同属工具目录，可在能力选择中明确辨认。
- 知识库为多个独立库：增加库实体与文档 library_id；原 group 保留为可选标签。复用现有原文、解析/切片、embedding、FTS/向量融合、版本与出处快照。
- 资源用“启用/停用、配置是否完整”等真实状态。接口测试成功只证明当次接口结果，不能冒充助手自动任务通过；写操作测试也是实际外部操作，不能绕过确认。

**助手设置**只有当前这一个助手：提示词、所选 API 工具 ID、所选库 ID，关联已有模型和声音设置。

- 复用现有“角色与声音”页扩展成助手配置。不新增 assistants 表、助手切换或面向未来多助手的结构；设置沿用 SettingsStore，不复制第二份可写提示词/模型/音色。
- 用“选入本助手”区分资源启停；选择为空表示该类能力不给，不默认回退到全部。已选但停用/缺配置的资源明确显示原因。
- 旧已启用能力映射为初始选择；旧资料归默认库、保留原分组并选入，以实际存量数据校验。迁移由 Lead 调度，本轮不执行；不得默默扩大范围或损坏原资料、历史、音色。

**对话**显示真实调用、结果/出处及必要确认，详情沿用现有洞察。不显示模型内部思维，不为普通问答堆流程。

## 4. 提示与检索范围

- 用户提示词管角色、服务范围、说话风格和业务偏好。系统从所选能力自动生成工具定义，用户不需要手写函数清单。
- 共用提示构建入口装配用户提示、当前日期时间、工具/依据规范、语音朗读规范和本轮必要状态。只注入相关片段，不把整库/全部历史塞给模型。
- 稳定工具 ID、用途、输入/输出说明、执行类型和权限由目录管理。密钥留在服务端，不交模型。提示词不能开放未选或停用能力。
- 实际检索范围是所选库与资源当前可用范围的交集。关键词和向量候选都须在排序/截断前按库硬过滤；模型传参只能进一步缩小范围，不能扩大。具体 SQL/索引修改在实现时核实，不能仅加一个筛选就声称没有漏召回。
- 一轮取一致的提示和选择范围，下一轮用新保存设置；真正执行前重查资源停用和权限。声音设置保留当前按音频段取值的既有行为，不因配置快照破坏语速/音调指令。

## 5. 执行与操作边界

1. 普通聊天直接回答，需要资料/数据时由模型选择已选工具；缺关键参数才询问。
2. 服务端校验选择范围、资源状态、参数与权限后执行，真实结果回模型。模型可继续查询、结合资料回答或说明失败，不能拿历史成功替代本轮执行。
3. 已明确开放的本地音量/声音控制保留自动执行和回读规则。外部修改/发送/删除/付费在接相应真实服务时，需要助手提出具体动作→用户明确确认→执行→回报；当前未接好确认的能力继续受限，不先建通用代办平台。
4. 确认绑定会话、工具与具体参数，只消费一次；参数变化重新确认。恢复时重查资源和权限，不能只信客户端 confirmed=true。网页可用卡片，设备在下一轮听取明确确认，不依赖播放中插话。
5. 取消终止尚未执行动作，迟到结果不能回灌新轮或重复执行。外部请求已经发出，取消不等于撤销副作用；超时可能结果未知，不能盲目重发。
6. 完成/失败/待信息或确认/取消/结果未知如实呈现。HTTP 成功不自动等于业务成功；依真实业务返回判断，没有确认依据就不能说办成。
7. 沿用现有历史/洞察关联问题、轮次、工具输入/结果和最终回答。对话记录不是长期记忆，不自动全量提取个人记忆；不做跨天自治任务或任务平台。

AEC/收放同听是设备约束，与 Agent 定义无关。当前固件未声明 AEC，上游未向该板开放标准设备端 AEC；播放时几乎无上行是日志推断，不当成硬件永久无能力。按键 abort 有实际记录，不能宣称当前已支持说话打断。出处/详细结果进网页历史，语音只播适合朗读的简短内容。

- API 管理（参考图2）：左侧搜索/列表/新增，右侧复用可视化/JSON、参数/头/鉴权/请求体、输出、测试和保存。内置条目只显示适用配置。
- 多库管理（参考图3）：左库列表，右文档搜索/上传、处理状态、预览/下载/替换/标签/删除及分页，保留正文/片段/试查入口。
- 对话按需显示“查询天气/检索资料”、实际能力和出处，失败原因清楚，详细链路进已有洞察。沿用整页两栏、灰阶主题和桌面布局，不为了新能力堆按钮或独立后台。

自然流程：管理资源→在助手配置选入→保存→直接聊天。资源保存不暗中扩大助手使用范围。

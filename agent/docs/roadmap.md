# 后续功能与协作实施清单

## 2026-11-08 目标收敛（当前有效，取代下方冲突的扩张表述）

产品目标：**一个个人硬件语音助手**——正常聊天 + 按需调 API／知识库办事，简单、高效、快速。不做多助手系统、长期记忆或重载规划平台。下文 P0–P3、主/子 Bot 分工中与此冲突的扩张理解按本节收敛；真实证据与未完成项保留不改写。

- 资源层：API 能力（天气/M5/自定义 API 合成一个列表）+ 多独立知识库；资源「启用/停用」。
- 助手层：一个助手集中配置＝提示词＋选入 API 能力＋选入知识库；「选入本助手」与资源启用分开。
- 对话层：模型判断→调用工具→按真实结果回答；需要连续多步沿用现有循环。写操作“先提出→用户确认→执行”的通用能力只在**实际接入写服务时按需补**；本期先把查询/读取类工具用顺，不强推通用写确认。
- 知识库：多库，服务端按库硬过滤；旧资料迁默认库，group 降权为可选标签。
- 推进顺序（依赖顺序，不逐步签字）：① 定底层契约+存量映射+收敛文档；② 助手选择+多库打通+迁移；③ 多步工具与（按需）写操作确认；④ 整体验证收口。

日期：2026-11-07。本文是剩余工作的统一计划，取代此前 M0–M5 的实施顺序及旧 P1/P2 插件候选计划。产品要求看 [PRD](prd.md)，实际实现和运行结果只记 [progress](progress.md)。主 DeepSeek Bot 的启动提示词见 [handoff](handoff.md)。

本文是剩余工作的统一计划。文档已于 2026-11-08 同步到单硬件语音助手目标；此前“只整理文档、未派工/未开发”是历史状态，部分能力现已实现（见 [progress](progress.md)），后续按用户最新指令推进，未完成项仍标未确认。

## 1. 项目目标与当前基线

- 最终使用端是 AtomS3R + Echo Base。网页用于管理、联调和辅助对话，不以网页能播声代替设备可用。
- 本地目录 `E:\xiaodan`；Python/FastAPI、原生 HTML/CSS/JavaScript、SQLite、小智兼容设备网关。
- 日常主方案为百炼 `qwen3.8-omni-flash-realtime`；实时模式下设备语音、网页语音和网页文字都用实时模型。DeepSeek/MiMo 仅保留在分模型模式，不自动混用或作为隐式兜底。
- 已有 API 接入的实时／分模型分页、共用 M5Stack 官方资料检索、中文音色与试听、百炼复刻音色、角色提示词与音量／语速／音调。
- 用户已经实际使用并确认基本交流正常。塔菲录音仍在 `models/voice/`，百炼复刻创建和试听成功；不要重复创建、覆盖或删除已有音色。
- 已有会话历史与设备控制代码；是否满足完整结束、重连、长期历史等行为，需要对照实际代码补齐，不能照旧计划重复开发。
- 尚未正式部署到目标 2 核 2GB 云服务器。最终设备、网页管理及历史不能依赖 Windows 开机。

基本交流正常，不等于打断、30 秒静默、回声、短断恢复、备份等都已通过。一次瞬时离线也不能据此断言硬件不可用。

## 2. 工作方法：AI 先完成，用户再集中体验

### AI 负责

1. 读懂现有实现和真实缺口，完成范围内完整功能；已有可用部分复用，不因换 Bot 重新造轮子。
2. 在真实代码与已授权的实际环境运行功能。接口调用、保存／恢复、服务日志和数据结果等能独立确认的事项，由 AI 自己完成。
3. 发现实际失败就定位根因并修复；完成后交付可使用的结果，不只给方案、示例或状态标记。
4. 如实报告“已开发”“AI 实际运行确认”“待用户现场确认”；不能用其中一种替代另一种。
5. 为用户输出一份合并的现场使用清单，不让用户每完成一个小改动就配合测试。
6. 遇到指定 API、资料或部署凭据缺失时，完成不依赖它们的工作，汇总真正缺失的信息；不编造服务、假数据或测试通过结果。

### 用户负责

提供实际要接的服务、资料和必要的账号配置；负责需要本人说话、听声音、按设备按钮、移动到客厅、断开家中网络、关闭 Windows 等物理条件的现场体验，并反馈问题。

### 明确不采用

不安排冒烟测试、模拟 API、假数据流程、测试隔离环境、最小可行性阶段、分级验收、影子环境或额外测试后台。不把覆盖率、截图、类型检查和文档数量作为主要交付。不为假想故障增加通用容错框架、自动换供应商或复杂状态机。

已有必要鉴权、密钥保护、输入校验、取消与并发一致性、数据保护继续保留。AI 可以按实际改动做必要的正确性检查，但不能把这些检查包装成一套先于功能交付的固定门槛。

### 推进顺序

推进依本文顶部 2026-11-08 的①–④依赖顺序与 [architecture](architecture.md) 进行：底层契约与存量映射→助手选择/多库→基础工具调用用顺→整体验证收口。P0–P3 只保留作功能分类，不要求先清完 P0 才开始工具/知识库，也不因等待听感或硬件限制停住独立工作。云端与备份按相应授权和配置实施；AI 先完成能独立确认的实际工作，用户集中体验，不逐步签字。

## 3. 功能清单、设计与责任

### P0：设备核心交互

| 工作项 | 设计与 AI 交付 | 用户现场测试 |
| --- | --- | --- |
| 段内多轮对话 | 一次唤醒开启当前段；最近有限轮参与上下文，完整文字历史独立持久化；设备与网页复用业务层 | 连续聊三轮，包含“刚才说到哪里”“把第二条展开”等上下文问题 |
| 播放中打断 | 停止旧回答并清空待播音频；取消旧生成，迟到数据不能回灌；新输入继续当前段 | 回答播放中直接插话，检查是否立即停止、有无丢掉新问题开头或新旧回答重叠 |
| 静默结束与重新唤醒 | 实际播完后无发言 30 秒结束本段；生成／播放时不能提前开始静默计时；再唤醒新建会话，旧历史保留 | 等待 30 秒后再唤醒，确认不沿用上段上下文 |
| 按键与语音结束 | 正面屏幕键立即停止并待机；明确结束意图结束当前段，普通引用“再见”等词不结束 | 收音、回答时分别按键；分别说“不聊了”和“再见用英语怎么说” |
| 断线恢复 | 恢复尚未结束的当前段，不重播旧音频、不重复已提交的付费请求；已结束的段不复活 | 短暂断开网络并恢复，判断是否重播、重复回答或丢失当前对话 |
| 唤醒与回声适配 | 使用现有固件的唤醒／按键／AEC 能力；核实实际能力，不靠无依据参数或烧录改变硬件 | 近距离、1～2 米、电视背景下讲话；确认不会把自己的回答反复识别 |
| 唤醒反馈 | 被唤醒时给出明确反馈（提示音与/或屏幕明确进入“聆听”），让用户知道已被唤醒 | 叫“塔菲”后能否立刻知道已被唤醒 |
| 语音结束与再唤醒 | “闭嘴/关机”结束当前段并回到待机；再次叫名字能重新唤醒并开启新段 | 说“闭嘴/关机”后是否回待机、再叫名字能否唤醒 |

AI 完成依据：真实业务路径可运行，按协议和已有事件完成会话、停止、结束和恢复；无法从远程数据判断的物理效果明确留给用户。首声目标约 3 秒，网关首包与扬声器出声必须分别表述。

### P1：外部 API 工具调用

“API 工具调用”指助手主动调用外部服务，不是已完成的百炼模型连接配置。

| 工作项 | 设计与 AI 交付 | 用户现场测试 |
| --- | --- | --- |
| 统一工具入口 | 复用已有实时函数调用能力，统一名称、用途、参数、返回结果和权限定义；供实时和分模型路径使用；没有工具调用能力的模型如实显示支持范围 | 在设备和网页分别提出需要查外部服务的真实问题 |
| 服务接入与配置 | 提供配置入口，管理服务地址、服务端鉴权、允许的接口和启停；无需每个服务改一次聊天主流程 | 配置自己要用的服务，检查步骤是否容易理解 |
| 真正执行与回答 | 模型提出调用，服务端校验和执行，把真实结果交回模型；失败如实回答，不伪造成功，不把密钥放进模型上下文 | 对照服务原始结果，判断工具是否选对、参数是否理解正确 |
| 操作权限 | 查询在授权范围内执行；发送、修改、删除、付费等动作按具体工具权限处理；需要确认的动作明确说明内容；写操作超时不盲目重提 | 对已明确开放的操作验证执行结果；未开放动作不能自动执行 |
| 首批业务工具 | 天气已接入（Open-Meteo，无密钥；当前实况+未来多日，已实测）；M5 官方资料检索已有；自定义 API 由用户按需配置。目标明确后接真实接口 | 指定实际服务、用途，配置对应凭据并使用 |

不做插件市场、任意代码执行器或复杂工作流平台。地址、模型参数和接口协议查官方资料，不能猜测。个人服务密钥在私有配置输入，不在群里粘贴。

### P1：个人知识库

新增个人知识库，不与现有 M5Stack 官方资料检索混淆。先按文件上传设计；下面的文件格式为建议初始范围，不代表已实现。

| 工作项 | 设计与 AI 交付 | 用户现场测试 |
| --- | --- | --- |
| 资料管理 | 上传、命名、分组、替换和删除；界面显示处理中、可查询或实际失败原因；建议先支持 TXT、Markdown、可提取文字的 PDF、DOCX | 上传真实常用资料，判断管理是否清楚 |
| 建立与更新索引 | 保存原文，拆段并建立可更新的索引；不每轮把整份文档送给模型；替换／删除同步移除旧索引 | 修改、替换或删除一份资料后重新提问，确认不再引用旧内容 |
| 查询与出处 | 共用工具入口，检索相关段落后回答；网页显示文件名、页码或可定位片段，设备简短播报，详细出处进历史 | 用熟悉的问题检查准确性、漏项和出处 |
| 无依据处理 | 没查到就明确说未找到，区分资料内容和模型推断；检索结果作为资料而非执行指令 | 提问资料中没有的内容，检查是否编造 |
| 轻量运行与接入 | 检索模块和模型接入分开；按 2 核 2GB 目标选择索引实现，不预建数据库集群，不在服务器常驻大型本地模型 | 后续云端使用真实规模资料，确认速度和稳定性 |

扫描件 OCR、网页抓取、网盘同步、定时采集先不纳入；待真实需求明确后追加。长期记忆与个人知识库是不同功能，本轮不自动加入长期记忆。

### P2：日常管理、声音与费用

| 工作项 | 设计与 AI 交付 | 用户现场测试 |
| --- | --- | --- |
| 统一能力区域 | API 接入只管模型连接；外部工具、个人知识库和官方资料检索统一管理；切换模式后仍能找到同一能力入口；不另建第二套后台 | 切换模式、启停工具、选知识库，判断是否容易操作 |
| 角色和声音完善 | 保留已完成的角色、中文音色、复刻与试听；验证保存恢复和设备／网页一致性；音量下发与实际读回、语速音调输出区分 | 选预置或塔菲复刻音色，调节语速、音调和音量，重新唤醒确认 |
| 聊天历史 | 列表分页、详情按需加载、重命名、导出、手动删除；记录必要工具摘要和资料出处，不长期保存录音；保存设置不清空历史 | 刷新、切会话、查看旧记录、删除和导出；网页操作不打断设备活动 |
| 用量清楚 | 区分文字、语音、试听、复刻与工具来源；保留供应商返回的文本／音频明细和准确统计口径；缺少数据不编造费用 | 对照百炼控制台，理解每种使用的实际消耗 |
| 降低无效开销 | 精简提示词和无关上下文；避免重复请求、背景音误触与无限增长的活跃上下文；不牺牲已确认角色和多轮能力 | 用同样日常问题判断回答与角色是否保留，观察长期费用 |

费用展示优先在现有消息或设置结构中表达，不默认恢复已删除的独立用量页面。费用规则核实后再显示，不把一次音频估算当成整月总费承诺。

### P3：云端运行与交付

| 工作项 | 设计与 AI 交付 | 用户现场测试 |
| --- | --- | --- |
| 独立部署 | 获授权后部署到目标 2 核 2GB，独立目录／端口，保护旧服务；不把当前本机服务直接暴露公网 | 关闭 Windows 后，用设备继续交流 |

| 数据迁移 | 保护现有配置、音色和文字历史；明确本机与云端的数据归属，不静默合并不同来源 | 核对需要保留的历史与音色 |
| 每日备份 | 独立存储每日备份文字历史，副本保留 30 天；完成一次实际恢复但不覆盖在线库；知识库原文／索引的备份范围需另行确认 | 在 AI 完成真实备份恢复后，核对指定历史内容；不需要用户等待 30 天才能开始使用 |
| 资源与使用说明 | 核对真实 CPU／内存／磁盘和旧服务影响，保留简短启动、恢复与排错说明 | 连续日常使用，反馈停顿、断连和操作困难 |

公网部署、服务器写入、设备接入地址改动、下载／安装、固件烧录和额外付费服务不因写入计划自动获得授权。仍不烧录；部署目标、凭据和备份目的地需由用户在实际执行时提供或授权。已有本地模型 API 使用不等于允许遍历模型、批量复刻或无限重复付费测试。

### 远期：Windows／Mac 电脑控制

目前只记录方向，不开发、不安装、不操作电脑。未来可由目标电脑上的本机执行程序接入统一工具协议；具体权限、应用操作、文件范围及反馈机制以后单独确定。不提前增加电脑控制框架，不把电脑在线作为当前设备助手的运行依赖。

## 4. 主 Bot 和子 Bot 的分工（开发执行分工，不是产品多助手）

> 说明：本节指开发团队的主/子 Bot 分工，与产品形态无关；产品只有一个语音助手，不做多助手系统（见 2026-11-08 目标收敛）。执行组织由 Lead 决定。

### 先盘点，再决定是否创建

主 DeepSeek Bot 先盘点可调用的现有子 Bot：能力、当前任务、工作目录／仓库权限、运行环境以及是否能操作真实项目。能复用则复用；缺少明确职责才创建项目专用子 Bot。以下是职责，不要求每项都新建一个 Bot：

| 职责 | 建议负责范围 | 关键交付 |
| --- | --- | --- |
| 主 Bot／集成负责人 | 范围、依赖、接口约定、文件归属、最终合入与运行、用户反馈汇总 | 统一结果和现场清单，不直接重复子 Bot 正在做的工作 |
| 设备语音负责人 | P0，声音链路相关问题 | 设备会话与停止、重连的完整行为 |
| 工具与知识库负责人 | P1，共用工具接口和资料处理 | 真正可配置、可调用、可查询的功能 |
| 管理界面负责人 | P2 界面、历史与用量，消费 P1 的已确定接口 | 沿用灰阶简洁 UI，无重复功能入口 |
| 云端运行负责人 | P3 的代码准备、获授权后的部署和备份 | 独立运行与真实恢复结果 |

同一个 Bot 可以承担多个职责。不要按文件数量建 Bot，也不要默认成立测试 Bot、审批 Bot、状态汇报 Bot。

### 创建／复用后先明确工作规范

主 Bot 在派工前为每个执行 Bot 写清：目标、负责范围、允许修改的模块、输入与输出接口、前置依赖、不能操作的资源、完成依据和汇报方式。规范引用本项目 AGENTS 与本文，不复制一套有冲突的项目要求。

- 同一文件或关键模块同一时间只有一个修改负责人。`main.py`、`service.py`、`realtime.py`、`settings_store.py` 和 `app.js` 等共享文件必须明确归属，不能让多个 Bot 直接并发覆盖。
- 能用现有隔离工作目录／工作分支协作时沿用现有机制；没有则串行修改共享模块，不为此新建复杂协作基础设施，不自动创建分支或提交 Git。
- 设备、8000/8003 服务、数据库迁移、编译／数据处理以及真实付费调用统一调度；不得各自启动冲突实例、抢设备或重复调用。
- 先确定 P1 共用工具接口，再接知识库与界面。独立的轻量工作可并行，依赖相同核心代码的工作串行交接。
- 现有会话、SQLite、密钥与音色不得被“重建环境”清空。不把私人对话、录音、密钥或带令牌 URL 发进群聊。

### 群聊派工与汇报

由用户选择的主 Bot 在其有权限的群聊中实际派工；本次文档不代表 Codex 已发送消息或创建 Bot。群内每项任务只需明确：

> 目标 → 负责人 → 负责模块 → 依赖 → 实际可用结果 → 剩余现场事项。

执行 Bot 完成自己的完整任务后交回主 Bot，由主 Bot 集成运行。遇到跨模块冲突交给主 Bot 裁定，不自行覆盖其他 Bot 的工作。不要只报“测试通过”或“已完成”，须说明实际输入、输出及限制；没有访问项目／设备的 Bot 只能做分析，不能声称实际开发或实机验证完成。

## 5. 统一给用户的现场使用清单

由主 Bot 在相关功能做完后一次性整理实际可用项目及路径；未完成的项目明确注明，不要求用户用坏功能做无意义测试。

| 用户动作 | 观察什么 |
| --- | --- |
| 唤醒后连聊三轮 | 理解上下文，不突然换角色或忘记刚才的问题 |
| 回答时插话 | 旧声及时停止，新问题开头完整，不混播 |
| 回答播完等 30 秒，再唤醒 | 正确待机，新段不引用上段隐私 |
| 按键结束、说“不聊了”、询问“再见用英语怎么说” | 前两种能结束，后者正常回答 |
| 近距离／客厅／电视背景下交流 | 识别、回声、接话速度和误唤醒表现 |
| 短暂断网并恢复 | 不重复播报或执行动作，恢复行为符合说明 |
| 选择预置／复刻音色，调整声音并保存 | 设备与网页一致，重连后保持，听感合适 |
| 用自然语言调用首批真实 API | 选对服务和参数，结果与服务端一致 |
| 上传自己的资料并询问、替换、删除后再问 | 能找到依据和出处，旧资料不继续被引用 |
| 手机／电脑查看、导出、删除历史 | 记录正确，设置保存不清历史，不干扰设备 |
| 云端交付后关闭 Windows，再用手机外网和设备 | 三项核心功能独立运行且私人页面有登录保护 |
| 核对一份已恢复的备份内容 | 用户指定的历史完整，在线数据没有被覆盖 |

用户反馈用自然语言即可。推荐包含：大致时间、设备或网页、说了什么／做了什么、期望结果、实际结果。主 Bot 应先查已有日志与代码，不要求用户提供密钥或重复做 AI 能自行完成的排查。

## 6. 尚需用户提供的信息

1. 首批外部 API 的实际服务与用途；密钥通过私有配置填写，不在群聊发送。
2. 个人知识库的真实资料与主要问题；文件上传为当前建议入口，格式范围待实际资料确认。
3. 执行 P3 时的域名、服务器写入授权和备份目的地；没有这些仍可完成本地开发及部署代码准备。
4. 主 Bot 所在平台、群聊与现有子 Bot 的权限由主 Bot 在自身环境确认；无法访问 `E:\xiaodan` 时先说明，不虚构已派工或已完成。

这些信息缺失只阻塞直接依赖它们的动作，不能成为暂停整个项目的理由。

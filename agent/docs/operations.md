> - **设置页现状**：整页两栏（左功能列表/右内容），「助手配置」集中提示词、选 API、选库及现有声音设置；「能力管理」统一 API 列表与多库管理。资源启用后可选入助手，启用不等于选入；空选择不默认全开放。三页、真实迁移及资料操作已运行确认，最新文字组合、引用和取消证据见 [progress](progress.md)。旧居中弹窗/三页签与“尚未实现”属于历史状态。
> - **已确认可用（AI 接口级）**：基础设备对话可正常交流；真实文字 RAG 检索并引用成功；天气接口真实调用成功。**未确认**：真实付费 TTS/复刻合成的实际听感与计费、实机完整语音回合端到端、公网/云端部署。

## 2. 配置和接口参考

配置来自服务端环境变量或项目根私有 `.env`，环境变量优先。已有变量覆盖时页面会显示变量名并拒绝误导性保存；手工修改需重启，网页保存即时应用且保留对话。密钥输入留空保留原值，响应不返回已有密钥。

「角色与声音」（整页两栏其中一区）先填文字/语音根地址与密钥，再选对话模型和声音、按需测试/试听，最后“保存选择”（旧 `/settings#api` 为历史兼容入口）。三项操作独立，获取列表不选模型、不测试模型；草稿测试不保存、不修改聊天统计或历史；保存不发起模型调用，后续聊天使用新配置。失败保留输入，成功保存清空密钥框；更改根地址必须重新输入密钥，禁止隐式把旧密钥发往新地址。

列表协议默认`auto`：只支持已核实的TokenDance `https://tokendance.space/gateway/v1`与OpenAI `https://api.openai.com/v1`。TokenDance公开列表无需密钥且不发送密钥，只列出声明支持Chat Completions的模型；OpenAI列表使用填写或已有密钥。其他地址须用户先核实文档后选择“已确认支持 OpenAI GET /models”，或选“不支持列表，手动填写”；不自动探测不同端点。列表成功不代表账户有调用权限或模型能用，仍须测试所选模型。

| 配置 | 当前意义与默认值 |
| --- | --- |
| `AI_PROVIDER` / `AI_BASE_URL` / `AI_MODEL` / `AI_API_KEY` | 供应商显示名、API根地址、准确模型ID、服务端密钥；地址不追加 `/chat/completions` |
| `AI_MODELS_PROTOCOL` | `auto`默认，仅核实地址；`openai`为用户确认的GET /models；`disabled`不获取列表、手填ID |
| `AI_MAX_TOKENS` / `AI_TIMEOUT_SECONDS` | 回复上限512；单次请求超时30秒 |
| `AI_HISTORY_TURNS` / `AI_MAX_SESSIONS` | 模型最近6轮；可淘汰的内存会话缓存默认100，不限制永久历史数 |
| `AI_SYSTEM_PROMPT` | 角色页可编辑的系统提示词；保存后下一轮生效 |
| `AI_INPUT_PRICE_PER_MILLION` / `AI_OUTPUT_PRICE_PER_MILLION` / `AI_CURRENCY` | 每百万输入/输出价格与币种；未知不填，币种默认CNY不意味着价格已确认 |
| `AI_HISTORY_DB_PATH` | 完整历史SQLite路径，默认项目内data目录 |
| `AI_M5STACK_ENABLED` / `AI_M5STACK_TIMEOUT_SECONDS` | 官方资料能力默认启用但不主动访问；请求超时40秒 |

当前接口：`GET /health`、`POST /chat`、`GET /usage`、会话列表/详情/重命名/删除、设置读取/保存/草稿测试、`POST /api/settings/models`草稿列表、官方资料状态/检索、设备状态/登记/偏好/应用。列表接口沿用本机同源/X-Local-Settings保护，返回模型ID和`chat_verified: false`，不返回密钥。准确schema看现有FastAPI接口说明，不复制一套容易过时的schema。

`/health` 的 `upstream_verified` 只表示当前配置曾有成功聊天，不是实时上游探测。`POST /chat` 省略session_id创建会话；未知会话404，未配置503，上游拒绝502，限流503，超时504，输入错误422。上游原文不回显。

Token按供应商实际返回记录；费用用Decimal计算，缺少价格或对应Token为未知。`logs/usage.jsonl` 记录调用元信息和用量，不记聊天正文或密钥。进程聊天统计在重启/保存配置后重置，日志和完整历史保留；草稿测试单独记录，不算聊天统计。估算不是账单，取消/超时仍可能有未报告费用。

M5Stack 检索作为内置工具 `search_m5stack` 注册，**随工具循环由模型按需自动调用**（受 `AI_M5STACK_ENABLED` 开关；默认启用但不主动访问），不是“每次用户显式开启”。只允许只读 `knowledge_search`，检索当前问题再交模型，不发送完整历史给资料服务；工具失败如实返回、不伪造成功；最多5片段、正文合计6000字符，来源仅允许已核对的官方域名或仓库。资料作为外部数据，不能覆盖指令。

### 共用或独立的API连接

同一个TokenDance服务只填写上方地址与密钥一次，默认供文字/TTS共用；在“模型与声音”分别选模型和声音。只有语音采用不同服务/账户时，勾选“语音使用不同服务”并填写第二套。留空保留已有密钥，共用时不需要再输入语音密钥。

`AI_TTS_USE_TEXT_CONNECTION=true`使用公共连接；false显式独立。旧文件未设置时，已有不同语音密钥保留独立，未存语音密钥或两套地址/密钥相同则共用。共用通过服务端引用生效，不复制Key；独立配置仍在私有.env中保留，勾回独立模式可恢复。更换任何实际使用的地址仍需重新输入对应密钥。

### 独立语音配置与试听

使用不同语音服务时在“API接入”填写独立地址和密钥；“模型与声音”选择内置TTS与音色，或VoiceDesign及必填描述。试听使用已保存连接和当前声音草稿，再通过“保存选择”统一保存模型/声音；旧`/settings#tts`兼容进入日常页。已有密钥不返回，留空保留，换地址需重新输入。合成使用WAV并在浏览器点击播放，取消/改稿/离页会停止旧试听并释放临时音频，不保证供应商取消处理或计费。未接设备、未替文字聊天自动配音。

服务端变量为`AI_TTS_BASE_URL`、`AI_TTS_API_KEY`、`AI_TTS_MODEL`、`AI_TTS_VOICE`、`AI_TTS_INSTRUCTION`、`AI_TTS_TIMEOUT_SECONDS`；只存私有.env，文字保存不会覆盖TTS字段。接口为`GET/PUT /api/settings/tts`和`POST /api/settings/tts/preview`（JSON含config及text，成功返回audio/wav，失败返回稳定错误）。所有接口沿用本机/同源/Host保护。试听不写聊天历史/日志或音频文件，现有用量只统计文字。

- 服务器已知 Python 3.11；requirements-speech.txt 为其选择 NumPy 2.3.5、PyAV 18.0.0，Python 3.12+ 保留本机 2.5.4/19.0.1。版本及 Linux x86_64 轮子已读官方元数据，未在 Linux 安装。系统仍需真实可用的 libopus 和 FFmpeg，不能以元数据存在宣称可运行。
- `AI_PUBLIC_ORIGIN` 留空时沿用本机模式；配置后仅接受一个 HTTPS origin，不含路径、查询或凭据。设备接入 URL 使用该 origin，OTA 返回对应 WSS URL。该地址由服务端固定配置生成，不相信浏览器请求中的 Host/转发头。网页设备页会隐藏无用的局域网 IP，保存配置本身不切换机器人。
- 公网模式要求至少32字符的 `AI_ADMIN_PROXY_TOKEN`，管理应用只接受回环连接和匹配代理凭据；Caddy 在个人密码认证成功后覆盖该凭据头。应用继续校验真实同源和写请求头，部署字段不能通过网页表单修改，也不回传代理凭据。启动必须使用 runner 的 `--public`，不能把旧本机入口直接监听公网。

部署时只需一份访问配置：`AI_PUBLIC_ORIGIN`、`AI_ADMIN_PROXY_TOKEN`、`AI_ADMIN_PORT`、`AI_DEVICE_PORT`、`ASSISTANT_ADMIN_USER`、`ASSISTANT_ADMIN_PASSWORD_HASH`。Caddy 与新应用从同一个 `/etc/xiaodan/access.env` 读取，示例内部端口8010/8013；模型地址/Key仍由 `/opt/xiaodan/.env` 管理，不传给 Caddy。密码哈希用现有 Caddy 的交互式 `hash-password` 生成，代理凭据应随机生成；本轮没有创建或显示任何真实凭据。

新服务的管理和设备端口均只绑定回环，Uvicorn 不信任转发头；公网由现有 Caddy 的80/443承接。实际部署前需核对端口占用，不能停旧站腾端口；需核对现有 Caddy 对 `basic_auth` 和日志 filter 的支持，不能擅自升级。

**日志必须完整处理**：本站片段已过滤 OTA URL 的 `key` 和敏感认证头，但既有 Caddy 全局错误日志也可能包含请求 URI。部署时必须将同样的 `format filter` 规则合并到现有默认错误日志编码配置，保留原有日志输出与审计；只过滤访问日志不够。设备网关自身不写 URI access log，识别日志只记录字数/耗时，不写聊天正文。未核对真实 Caddy 配置前，不宣称公网日志已经安全。

只迁移程序、社区核心/VAD、确实采用的语音资源及经过一致性保护的历史/私有配置，不上传 Windows 虚拟环境、Kokoro 候选、缓存和旧产物。迁移必须保留设备配对凭据、原 OTA 记录和未删除历史，不用旧数据库覆盖新记录。现有 SenseVoice 跨平台支持不代表已确定2GB生产使用本地 ASR；实际资源与在线 ASR 选用仍按真实证据确定，不猜供应商接口。

服务器真实功能完成后，获得设备操作授权再把机器人自定义 OTA 地址改为该站点生成的接入 URL；服务器下发 WSS。此过程不自动烧录固件，不承诺尚未实跑的固件 TLS 兼容或原平台恢复。

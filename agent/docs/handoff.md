# Agent 接手说明

更新：2026-11-15。本文件只规定接手方式；当前版本与待办不在这里重复，见 [START](../START.md)。

## 接手顺序

1. 读根 [AGENTS](../../AGENTS.md)、[README](../../README.md)、[统一入口](../agent.md) 和 START。
2. 明确用户这轮要处理什么，特别留意暂停事项。当前卡顿表现已说明为整段回复随机停顿后继续，用户要求暂不解决；不再追问同一问题或自动开始采集。
3. 按任务读 [架构](architecture.md)、[操作手册](operations.md)、[代码地图](../code/structure.md)；需追溯某项事实时才检索 [progress](progress.md) 的对应日期/主题。
4. 区分运行副本 `E:\xiaodan`、真正 Git 工作树 `E:\xiaodan\.cache\repo-export`、云端 `/opt/xiaodan/current`。代码有意不同，文档保持同步。检查 Git 用工作树路径，不在运行目录重新初始化仓库。

## 新电脑接手

1. 从既有远端 `https://github.com/HunterLzap/xiaoyuan.git` clone；已有clone先查工作区是否有自己的未提交内容，再同步main，不强制覆盖。
2. 以 `git rev-parse --show-toplevel` 的实际目录为根，从AGENTS→START及相对链接阅读。原电脑E盘、用户名、PID、COM3和SSH私钥路径只是现场记录，不是新电脑必须具备的路径。
3. 当前main保存开发快照，包含保留的动画/UI/TCP实验；云端在线release和稳定基线单独见START。提交只是保存源码，不代表实验已部署、听感通过或允许直接运行/刷机。
4. 模型/设备Key、.env、数据库、知识库原文、音色录音样本、SSH私钥、虚拟环境和本地日志不在Git。**不复制原电脑的Windows虚拟环境，也不因未配置就保存空设置、生成新设备凭据或重新配OTA。**
5. 文档中的 `E:/xiaodan/output` / `logs` 原始证据链接只在原电脑可用；仓库保留progress里的结果摘要与范围。新电脑无法独立复核原附件时记“原始附件不在此机”，不能改为失败或补写已通过，也不默认重新付费跑。
6. 只阅读/修改源码文档无需模型密钥。确需启动本机或访问现有服务器时，再按具体任务确认必要环境与凭据，通过用户的安全渠道配置；不把密钥、私钥、数据库或聊天记录推入Git。

## 不要重复已经办完的事

- 云端已部署，设备 OTA 已切云且真实对话成功，不再把它当成待接入任务。
- 用户明确取消网页登录，不擅自加回账号密码；保留设备与传输保护。
- 助手能力/库选择、多库迁移、关键词及向量隔离已有真实证据，不因旧文重新迁移或建第二套助手系统。
- Token 明细、文字按任务工具与会话内按需历史已有实现；不能因语音尚未接任务工具加载，误称所有优化都没生效。
- 不再创建塔菲音色、改语速音调、切供应商或直接把语音拆成另一套 ASR→LLM→TTS。

## 必须保留的边界

稳定基线 `bd639a9` 与Git开发快照分开。新动画/UI/TCP改动在Git保留但不自动上线；工作区干净也不能整体覆盖稳定服务或重编译刷入设备。

11月15日稳定恢复用户确认有效；云端新一轮卡顿尚未定因。旧上游板级AEC不支持说明不能用来否定项目后来自己的播放参考/AEC实现与真实反馈；握手 `aec=true` 也不等于全部回声/打断场景通过。

已授权范围内自主推进。部署、刷机、改设备地址、下载安装、付费调用等以具体任务与已有授权为准；文档或密钥存在不自动扩大授权。AI自己查接口/日志/实际结果，用户只负责讲话、听感、按键等现场条件。

设备开串口/RTS曾造成复位和下载模式；不把串口读取当成必然无副作用。不得打印完整设备API、NVS、私有配置或带key地址，不打包私人数据到交接材料。

## 工作方式与交付

- 先复用官方/成熟项目做法，核实其与当前供应商、协议和硬件的差异，不为省Token丢掉复合指令和追问。
- 不默认建模拟API、假数据、影子环境、分级流程或额外测试后台；实际失败查根因，不反复运行无关检查或批量付费探查。
- 可用工具和本轮任务确有必要时才安排协作；不要求使用某个品牌主Bot、群聊、固定角色或新开聊天。协作同一文件同时只有一个负责人，服务/设备/付费由主负责人统一调度。
- 交付区分已有代码、AI实跑、用户现场确认；供应商完成、网关发完、设备收到、扬声器播放流畅分别表述。

更新当前事实写 START，运行证据写 progress，产品变化改 PRD/decisions，设计改 architecture，操作改 operations。不要在每个入口追加一套时间线或平行计划。

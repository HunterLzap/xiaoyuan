# 使用者与场景

## 核心使用者

设备所有者本人：希望有一个能正常聊天、并在需要时调用 API 与个人知识库把事办成的硬件语音助手，重视简单、快、成本和维护负担。当前没有其他用户、团队运维或对外提供服务的需求，也不需要多助手或复杂 Agent 平台。

## 第一版场景

| 场景 | 触发 | 希望得到什么 | 核心价值 |
| --- | --- | --- | --- |
| 与实体机器人交流 | 在设备旁主动发起对话 | 听到回答并能在后续一句继续交流 | 形成真实的硬件交互体验 |
| 修改自己的机器人 | 在管理网页选择设置并保存 | 设备使用选定模型、角色、声音或支持的硬件设置 | 自主掌控行为与配置 |
| 回看一次交流 | 打开历史并选择会话 | 找到当时的问答，刷新或重启后仍存在 | 可回顾、可排查，不要求重新问一遍 |
| 让助手用工具办事 | 问需要外部接口或个人资料的问题 | 助手按需调用已配置的 API 或所选知识库，按真实结果回答并说明来源 | 简单高效地办事，不编造 |

用户已确认安静桌面近距离与客厅约1–2米、可能有电视或音乐两种环境都必须能用；背景音和摆放在实测时记录，不扩大为任意噪声远场承诺。首声目标为实际说完后约3秒内听到回答，不是当前性能承诺。每天使用频率与每次时长仍未观察，不为项目编造高频刚需。

## 交互语气

中文、简洁、明确；以用户理解的行为描述状态。例如“设备未连接”“声音生成失败”，不用“系统正常”掩盖某个环节不可用。实体机器人的个性、名字和音色待用户选择。

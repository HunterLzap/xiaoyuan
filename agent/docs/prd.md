# 产品需求

更新：2026-11-15。本文定义产品行为；运行版本、已实现范围与暂停事项见 [START](../START.md)，不把目标写成已经验收。

## 产品范围

产品目标收敛为**一个个人硬件语音助手**：正常语音聊天，能理解需求，按需调用 API 与所选知识库把事办成，简单、高效、快速。具备基础工具反馈循环；**不做多助手系统、长期记忆或重型规划平台**，不是通用机器人/插件平台。

- 配置集中一处：助手提示词 + 选入哪些 API 能力 + 选入哪些知识库（多库，服务端按库硬过滤）。资源“启用/停用”与助手“选入”分开。
- API 能力统一为一个列表：天气、M5 官方资料、自定义 API。个人知识库独立于 M5 官方资料检索，二者都作为工具。
- 写操作（改/发/删/付费）按实际服务需要：助手先提出具体操作、用户确认后再执行；确认走下一轮说“确认”，不靠播放中插话。现有鉴权、密钥、数据保护不削弱。
- 判断是否 Agent 以“模型能否依据目标与工具结果决定下一步”为准，不以长期记忆/多规划器这些非必要条件衡量。R01 及相关处“个人机器人平台/插件扩展”按本节理解。

外部API工具与个人知识库均已进入产品范围；API工具不同于模型连接配置，个人知识库不同于M5官方资料。旧P0–P3/M0–M5不决定当前顺序。当前卡顿暂缓、本轮仅整理文档，不自动开启开发、部署或设备操作。

## R00 文档、授权与证据

统一入口为 [agent.md](../agent.md)。已实现代码、历史测试、真实账户/设备与云端验收分开记录，当前能力看 [progress](progress.md)。PRD 与文档同步不自动授权开发、部署、烧录或改设备，范围以用户最新明确指令为准。

按用户最新指令在明确授权范围内直接实现完整功能，按现有代码/前端规范执行，再集中与计划及相关验收比对；不要求另开对话，也不停在方案或模拟。避免假想兜底、无必要抽象和逐小改动反复测试，不削弱真实安全、数据一致性或必要验证。具体执行规则见 [代码规范](../code/conventions.md)。

## R01 为什么做、为谁做、做到哪里

为设备所有者本人建设一个可正常语音交流、按需调用 API 与个人知识库办成事的个人硬件语音助手。兴趣和自主掌控是有效动机，目前不编造高频效率刚需。以小智基础体验为参照，第一版必须有语音聊天、网页管理、聊天历史。

按已有一位使用者、一套AtomS3R + Echo Base作实施规划假设；这不是已确认的多账号、多设备或商业平台需求。个人知识库与外部 API 工具已加入 P1；电脑控制先不做，空调、长期记忆和插件市场不自动纳入。

| 核心场景 | 触发与交互 | 结果 | 失败处理 |
| --- | --- | --- | --- |
| 与机器人说话 | 待机唤醒或按键开始，段内自然追问 | 听到回答，小屏反馈关键状态，文字历史可查 | 区分无有效语音、识别/模型/合成失败与掉线，不伪报播放成功 |
| 管理机器人 | 手机/电脑访问免登录管理页，测试/保存/应用配置 | 后续对话或实机设置按配置生效 | 离线、不支持、未读回分别显示，保存失败不冒充成功 |
| 回看记录 | 在管理页选会话、搜索、查看、导出或手动删除 | 重启后仍能查看未删文字，删除有明确结果 | 存取失败明确提示，损坏库不自动清空，删除失败不伪报成功 |

## R02 运行方式、资源与API

- Windows本地开发测试，部署到已有2核2GB、40GB云服务器；正式交付后Windows关机，语音、管理、历史和自动备份都不依赖它。
- 接受在线ASR/聊天/TTS，供应商可替换。API由用户配置，费用自行管理，不要求月预算，不新增预算审批、消费额度或自动换供应商。
- 当前实时主线为百炼 `qwen3.8-omni-flash-realtime`，音色为百炼塔菲复刻（`AI_RT_VOICE`）；实时模式下设备/网页语音与网页文字同一模型。MiMo-V2.5-TTS、Kokoro、voice-studio 归分模型/历史候选，不写成当前可用。
- 复用现有对话、设置、历史、用量、设备网关与灰阶明暗工作区。旧voice-studio已被用户放弃，不作为接口复用前置；Windows Kokoro保留历史对照，不成为生产依赖。原平台保留绑定与恢复路径。
- 不在2GB云端默认装载本地语音或大模型，不复制Windows虚拟环境。云端端口、权限、目录及兼容性见 [architecture](architecture.md)，资源证据见 [resources](resources.md)。

## R03 唤醒与按键入口

第一版必须支持语音唤醒并保留正面屏幕按键。沿用现有“塔菲”与已恢复链路，不自动增加定制词、触屏、长按/连按新用途或服务端持续上传待机录音。不同启动/活动状态下的按键行为须按对应固件核对，不用单次现象替代全部确认。

若现有固件无法支持所需唤醒、按键或讲话打断，与暂不烧录冲突时，先提供证据与取舍，不擅自刷机、升级或降级为仅按键。

## R04 会话与上下文

- 待机中语音唤醒或按键发起，建立新业务会话；同一段内多轮复用上下文。识别文字进入统一ChatService，不再造一套声音专用历史。
- 正常说话和播放中语音打断留在当前段，不因每句话或底层WebSocket重建而新建会话。
- 本段结束后再次唤醒新建，不自动带入上一段问答。角色与系统提示词仍有效；旧文字记录保留，这不是长期记忆。
- 网页查看旧记录，不自动让下一次机器人唤醒继续该记录。已有网页文字聊天可复用，不强行与设备活动段绑定。
- 完整历史和模型最近N轮独立；设置保存不清空记录，不能把全部历史重新送模型。

### 会话状态与优先级（工程建议，落实上述已确认行为）

| 当前状态/事件 | 应有行为 | 会话和计时 |
| --- | --- | --- |
| 待机 → 唤醒/按键 | 接收新输入 | 新建一段 |
| 收音/识别/生成 | 正常处理，有界等待 | 不运行“播完后30秒”计时 |
| 播放回答 → 用户直接开口 | 停止旧播放，接收完整新发言 | 仍在本段，作语音打断 |
| 回答实际播放完成 | 等待追问 | 开始30秒静默计时 |
| 等待中用户继续讲话 | 取消旧计时，处理新发言 | 仍在本段，下一次播完重新计时 |
| 静默30秒/明确语音结束/活动中按键 | 停止交互，回待机 | 结束本段；不删除历史 |
| 网络短断/恢复 | 只恢复同一合法设备的未结束段 | 不重置有效期限，不重播旧回答 |
| 已结束后迟到结果/旧连接回调 | 不再接收为有效播放 | 不复活会话，不覆盖新连接 |

结束与按键优先于网络/模型返回，不能等模型请求完成才待机。无首个有效输入、空识别或失败后的等待也必须有界；其超时默认值属于实现建议，不冒充用户已经确认的“回答播完30秒”。

## R05 三种结束方式

1. 回答实际播完后30秒无人继续讲话，结束本段。收音、识别、模型生成、播放过程不计入该静默时间。
2. 明确说“不聊了/再见”等结束意图，结束本段并回待机，不必等30秒；引用“再见”或“帮我翻译再见”不能误触。
3. 活动中按一下正面屏幕键停止交互、结束本段并待机。下次唤醒是新会话，不是暂停续聊，旧历史仍保留。

停止会话收音上传不等于硬件麦克风完全断电；不宣称已经提供物理隐私静音。端侧唤醒仍按固件实际能力工作。

## R06 播放中语音打断

用户直接开口就停止旧回答并听取新输入，无需重复唤醒词，继续当前段。必须停止设备实际播声及旧缓存，不只是停止服务器发送；新发言开头不能因为停止流程丢失。自己的播声或背景电视不能循环触发无意义打断。

已生成文字保留并区分“已生成/实际播放/被打断”，不能声称整段已讲完。新问题之后旧轮次音频不得回灌。终止与迟到结果隔离是正确性机制，接口取消不等于供应商一定停止计费。打断停止延迟单独测量，不与回答首声混为一项。

## R07 失败与自动重连

- 无有效语音不给模型提交空问题；各阶段错误可理解，不无限等待，不自动重提ASR/模型/TTS。模型已有回复而合成/播放失败，保留文字，不重复问模型。
- 短暂网络断开自动重连，只把同一已鉴权设备接回尚未结束的本段，保留上下文，不重播旧回答。
- 30秒静默与处理超时仍有效；本段已结束则回待机重新唤醒，不能因重连复活。未完整收到的发言不能当成功输入，提示用户重说。
- 连通性重试与供应商请求重试分开；前者可有界退避，后者不自动重复。旧连接与迟到回调不得覆盖新连接或新轮次。
- 服务进程重启后的活动段处理不是“网络短断”的已确认承诺。工程建议重启先回待机、新唤醒建段，完整文字历史仍恢复；不自动重放中断回答。

## R08 双环境与约3秒首声

- 安静桌面近距离及客厅约1–2米、有日常电视/音乐两组都必须覆盖唤醒、识别、打断和回答。实际摆放、背景音、网络记录清楚，不扩成任意噪声或3/5米远场承诺。
- 首声目标从用户实际说完到实机扬声器开始播放回答，约3秒内；包括尾音结束检测、上行、ASR、模型、TTS、下行及播放缓冲。提示音和固定“正在处理”不算回答首声。
- 验收固定实际使用的模型、ASR/TTS、音色、网络和环境；更换配置后重测，不保证用户任意慢模型都达3秒，不自动换模型或截断回答来掩盖未达标。
- 约3秒是已确认目标，尚未实测。若达不到，记录每轮瓶颈，由用户基于证据决定是否调整；不能仅以平均值或健康状态宣布达成。

## R09 网页管理

用户已明确该项目个人使用、不需要网页登录，当前外网手机/电脑直接进入管理页；不擅自加回账号密码。HTTPS/WSS、独立设备凭据、内部代理令牌、同源及写请求校验继续保留；浏览器不能取得模型Key。免登录与取消设备鉴权是不同选择。

保留Codex风格明暗工作区、会话管理和文字聊天；设置改为整页两栏（左功能列表、右内容），含角色与声音、API接入、能力管理（工具/知识库两个选项卡）、数据洞察；API 工作台整页，同服务共用密钥、不同服务才独立。角色用系统提示词控制下一轮回复。能力「启用/停用」与助手「选入」、选知识库分开表述。取消恢复已存配置，失败保留输入，保存不清空历史。参数紧凑直接编辑，常规桌面一屏，手机必要滚动不裁剪。设备/用量刷新并入统一状态栏。M5Stack 官方资料检索与个人知识库为两个独立工具，均纳入统一工具管理；配置页可写提示词、选 API 能力、选知识库（多库）。

| 管理项 | 操作与结果 | 失败或生效边界 |
| --- | --- | --- |
| 模型/ASR/TTS连接 | 用户配置准确接口、模型、密钥；测试和保存分开 | 按实际适配器提供字段，不假定三种服务共用协议；已有密钥不返回网页 |
| 文字与MiMo TTS分离 | 默认文字/TTS共用一次配置的地址与密钥；仅选择“语音使用不同服务”时配置独立连接，在API接入分组保存；日常模型与声音选择原子保存。支持mimo-v2.5-tts内置音色与mimo-v2.5-tts-voicedesign描述，使用已保存连接试听草稿 | 共用模式由服务端引用同一凭据，不向浏览器返回密钥；独立模式不继承文字凭据；VoiceDesign描述必填；试听不保存/不改历史，失败保留输入，可取消浏览器请求/播放，不保证供应商停止计费；音频不长期落盘。不包含ASR、设备接入或语音闭环 |
| API配置入口与模型选择 | 点击明确的“API配置”入口，填写地址/密钥；一键获取模型列表后选择，也可手填模型ID | 用户后续自行配置，不要求现在提供资料；模型ID即接口识别模型的名称。只调用供应商已核实的列表接口，不支持/返回空/鉴权失败/超时应区分提示并保留输入；列出不代表已获权限或适合聊天，仍需实际测试，不自动试遍模型 |
| 角色与声音 | 提示词、验证过的来源/音色、试听、保存 | 角色名不是唤醒词；试听不等于设备播放通过 |
| 设备设置 | 状态、音量、亮度、主题、屏幕文字等实际支持项 | 保存、发送、回执、读回和人工效果区分，离线可保存但不显示已生效 |
| 历史与用量 | 切换、标题搜索、重命名、导出、删除；用量仅在每条回复显示 Token 与估算费用，无独立页面 | 未知Token/价格如实未知；保存配置不清空历史，删除失败不伪报成功 |

工程建议每轮使用开始时的配置快照，保存配置从后续轮次生效，避免同一句混用模型与音色；不因此阻塞按键结束或语音打断。具体同步方式保留等效一致性保护。

## R10 长期文字历史

只保存识别后的文字、模型回复和必要时间/已有用量与交互结果。不按30/90天自动删在线文字；只有用户主动删除，空间不足也不擅自清空，应提示真实失败。

完整历史持久化，列表分页、详情按需读取，活跃上下文有界；历史分页与按需加载已实现，容量保护保留（见 [progress](progress.md)）。重启/配置保存后可查未删记录，写入失败保留已生成回答并提示，坏库先保护数据。

本机SQLite、小智云记录、voice-studio是独立系统；不自动同步、导入原云历史或跨会话召回。

## R11 音频隐私

不长期保存用户录音，不提供历史录音回听。必要缓冲/临时音频在完成、失败、取消和异常退出后的恢复路径清理，不进入普通日志、历史库和长期备份；合成音频同样仅供处理/播放。已有非私人试听可保留。

在线服务接收相应录音或文字已获接受，供应商自身数据政策仍须核实，不能承诺本项目删除其内部记录。测试需校准音频时使用固定非私人样例或临时现场处理，不为留证据永久保存用户录音。

## R12 每日独立云备份

每天一次，备份副本保留30天，放独立云存储或另一服务器，不依赖Windows，不只留运行系统盘。在线文字历史仍一直保留；30天是副本轮换，不是在线历史期限。

具体服务/路径/权限待实施配置。时间点可配置，时区明确，按Asia/Shanghai设计；任务不重叠，一致性备份、校验、上传、过期清理顺序清楚。失败可见，不伪报成功，不影响正常聊天，不混入录音/临时音频或明文API密钥。

实施时用真实独立目标做一次实际恢复并核对记录（不搭隔离测试后台），不能仅看备份文件存在。恢复到最近成功副本不能保证此后新增内容零丢失。用户手动删除与旧副本的关系需明确：旧副本可能在30天内仍含旧记录，不冒充已经彻底擦除；恢复前保护当前状态并落实删除范围，不能静默复活已删历史。具体恢复与配置/凭据恢复方式属于实施方案，必要时在部署前确认。

## R13 设备切换与恢复约束

保留现有固件与原平台绑定，当前不再烧录。用户已将完整自定义OTA地址保存并完成云端真实对话，不再安排切换或拼接key；原字段空值属于历史恢复记录。只有用户明确要求恢复原平台时才按保留值操作，不猜默认地址。

能力协商、回执/读回与人工观察分别证明；屏幕文字事件不是声音，既有控制成功也不证明当前语音全部通过。当前已确认范围只看START/progress。原平台恢复须在不依赖自建网关时完成真实对话，不能只看在线状态，也不承诺网页一键切回。
